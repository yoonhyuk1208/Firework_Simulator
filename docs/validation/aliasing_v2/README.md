# V2 에일리어싱 기준선

카메라가 움직일 때의 반짝임은 시간축에서 본 에일리어싱이다. 표본 간격보다 가는
디테일은 픽셀 중심이 어디 떨어지느냐로 결정되므로, 카메라가 움직이면 값이
불연속으로 튄다. 원인은 움직임 없이도 보인다 — 같은 프레임을 더 높은 표본율로
렌더해 박스 필터로 되돌리면, 그 차이가 1× 렌더가 내고 있는 오차다.

## 방법

- `post` 이전의 **선형 HDR**을 비교한다. 블룸과 표시 변환은 픽셀 단위로 동작하므로
  초해상 렌더에서는 월드 스케일이 달라져, 그 차이를 재면 에일리어싱이 아니라
  후처리 스케일을 재게 된다
- 4× 초해상(5120×2880) → 박스 다운샘플 → 1× 렌더와 픽셀별 비교
- `assets/known_render_residuals.json`의 드라이버 잔차 영역은 제외한다. 재현된
  드라이버 차이를 에일리어싱으로 계상하지 않기 위해서다
- `visibly_wrong`은 상대오차 5% 초과 픽셀 비율이다. float16 저장 단차보다 충분히 위다

```powershell
python -m tools.measure_aliasing --supersample 4 --frames 8
```

## 기준선 (2026-09-11, Intel Arc 140V)

| 시점 | mean | p95 | visibly wrong |
|---|---:|---:|---:|
| road_ground | 8.92e-06 | 3.74e-05 | 10.94% |
| water_reflection | 2.00e-04 | 3.19e-04 | 17.11% |
| terrain_shoreline | 1.48e-04 | 2.42e-04 | 24.62% |
| grass_close | 1.65e-04 | 1.83e-04 | 35.17% |
| bridge_structure | 2.98e-04 | 6.16e-04 | 37.24% |
| **facade_landmark** | **6.32e-04** | **3.34e-03** | **62.17%** |

`facade_landmark`가 압도적으로 나쁘고 p95는 다른 시점보다 한 자릿수 위다. 파사드가
주제인 시점이 가장 심하다는 점은 V0-8의 측정과 독립적으로 맞물린다 — 그때 1.5km
파사드가 창 셀당 **2픽셀 미만**(가로 1.90, 세로 1.72)으로 표본화됨을 확인했다.

`water_reflection`의 최악 블록은 행 320~352 대역에 열 32~1136으로 넓게 퍼져 있다.
한 건물이 아니라 **지평선 스카이라인 밴드 전체**가 원인이다.

## 한계

- 박스 필터 초해상은 1× 렌더보다 나은 기준일 뿐 정답(ground truth)은 아니다
- 앰비언트 오클루전과 반사 사전 패스는 해상도 비례 버퍼를 쓰므로 기준 쪽에서도
  표본화가 개선된다. 따라서 이 수치는 순수 기하 에일리어싱만이 아니다

## 반증된 가설 (2026-09-11, V2-3b)

기준선을 근거로 수정을 시도했고 **세 가설이 모두 반증됐다**. 셰이더는 되돌렸다.

### 1. 창 격자 per-cell 난수의 나이키스트 미달 — 반증

셀 발자국이 2픽셀 미만이면 per-cell 난수를 각자의 기댓값으로 수렴시키도록
`cell_detail = 1 - smoothstep(.5, 1, cells_per_pixel)`를 넣고 `occupied`·`room_dimmer`·
`floor_blackout`·`temperature`·`pane`·블라인드·커튼을 페이드했다. 기댓값은 상수로 적지
않고 같은 경계값에서 유도했다(`E[step(t,u)] = 1-t`, `E[smoothstep(a,b,u)] = 1-(a+b)/2`).

결과: **facade_landmark 62.17% → 62.17%(무변화)**, water_reflection 17.11% → **17.58%로
악화**. 원거리에서만 걸리는 페이드라 이 시점들에서는 거의 발동하지 않았다.

### 2. 기하 실루엣 에일리어싱 — 반증

`facade_landmark`의 커버리지는 **100%**다. 하늘이 없어 실루엣 픽셀이 **0개**이고,
오차 62.17%는 전부 내부 표면이다.

### 3. 스캔 재질 노멀맵 — 반증

`n = normalize(mix(n, mapped_normal, detail))` 한 줄을 진단용으로 비활성화하고 측정하니
**mean·p95·비율이 모두 바이트 단위로 동일**했다. 이 표면들에는 스캔 재질이 적용되지
않는다(`scanned_layer_for_material`이 -1을 반환하는 것으로 보인다). 측정 후 되돌렸다.

### 재현성 확인

되돌린 뒤 `water_reflection`이 기준선과 **정확히 일치**했다
(mean 1.9977e-04, p95 3.1859e-04, 17.11%). 측정이 재현 가능함을 확인한다.

## 이 지표의 중요한 한계 (추가)

**발자국 기반 LOD 페이드는 이 지표로 판정할 수 없다.** 초해상 기준은 발자국이 4배
작으므로 페이드가 덜 걸린 더 상세한 영상이 되고, 1×에서 올바르게 수렴시킬수록 기준과의
차이는 오히려 **커진다**. 위 가설 1에서 water_reflection이 악화된 것이 이 효과다.

따라서 이 지표는 "정적 프레임이 더 높은 표본율의 결과와 얼마나 다른가"는 재지만,
**LOD 수렴이 옳은지는 재지 못한다.** 움직임 중 반짝임을 판정하려면 카메라 이동 중
시간축 안정성(V0-2의 `temporal_stability`)으로 재야 하며, 거기서는 LOD 수렴이
점수를 **개선**시킨다.
